# A03. The arithmetic residue of t >= 7, and an exact SAT spec for it

**Family.** n = 18, T = 94 assumed, no 4-fold point, exactly t >= 7 triple points.
This claim is a *reduction*, not a closure: it turns the family into a small system of
cardinality constraints plus a named list of structures, ready for a solver run in the style
of `work/loop/claims/C32_spec.md`.

## Statement (residue system)

With the notation of A01 (m, sigma = 3t - m, B, beta, Z, C, n_i) a 94 with t >= 7 satisfies
all of:

- (R-a) B + beta = 3t - 6 + Z  (C34 (a), equivalently sum_P c(P) = t - 6 + Z);
- (R-b) beta <= sigma = 3t - m  (A01);
- (R-c) B <= 2t + C, hence **B >= m + Z - 6** and **m + Z <= 2t + 6 + C**  (A01);
- (R-d) n_2 + 2 n_3 >= B - t >= m + Z - 6 - t: at least m + Z - 6 - t triple points carry two
  blocks (counting centroids twice);
- (R-e) beta >= t - 6 + Z - C >= 1: at least one pair of triple points is consecutive on a
  shared line and joined by a doubly used segment;
- (R-f) every point with b >= 2 either gives a Lemma-A touch or has a cap line through
  another triple point ("killed"); the touches are distinct pairs (unused segment, endpoint),
  and 2Z = sum_L kappa(L) + Z_tr, so

  **#killed points with b >= 2  >=  (n_2 + n_3) - 2Z**;

- (R-g) sigma = 3t - m >= 3t - 18 >= 3, i.e. the total excess sum_L (j_L - 1) is at least
  3t - 18, so at least ceil((3t - 18)/7) lines carry two or more triple points (j_L <= 8) and
  the parity claims C6 / C11 / C13 apply to them;
- (R-h) per-point type table (C07 verdict, C34 (b)): c(P) = b + e/2 - 2 with
  c <= 2 (axis, and only with an all-multiple face per bridge, Lemma B),
  c <= 2 (bent; c > 1/2 needs a second multiple first vertex on a cap, c = 2 needs
  Q, V0, V4, V5 all triple), c = e/2 - 1 (1 block), c = e/2 - 2 (0 blocks), c = 5/2
  (centroid). Every bridge end at an axis point or a centroid is charged in x (A02).

**Consequence at t = 7 (C = 0).** m ranges over 7..18 (m >= 7 because 3t <= C(m,2)), and
- Z <= 20 - m, so m = 18 forces Z <= 2, m = 17 forces Z <= 3;
- B >= m + Z - 6 and B <= 14, so at m = 18: B >= 12 + Z, i.e. at least 5 + Z of the 7 points
  have two blocks;
- beta <= 21 - m and beta >= 1 + Z;
- at m = 18: #killed >= 5 + Z - 2Z = 5 - Z >= 3, so at least three of the seven points have a
  cap line through another triple point (a mutual-pair-like structure), while Z <= 2 leaves at
  most 4 touches in total.

Larger t only tightens (R-e): beta >= t - 6 + Z - C grows, and every bridge needs either an
all-multiple face (axis ends, Lemma B) or an end at a bent back ray / 1-block / 0-block point
(A02 item 5).

## What is *not* proven

The system above is satisfiable arithmetically for every t in 7..18 (e.g. t = 7, m = 18,
Z = 0, B = 12, beta = 3, n_2 = 5, n_1 = 2). Closing t >= 7 needs one of:

1. a lower bound on Z from the triple lines (C6 / C11 / C13 parity on the sigma >= 3t - 18
   shared lines, plus C20-style unused-or-ray credits at bent back rays): Z >= 3 already
   kills m = 18 at t = 7, and Z >= 2t + 7 - m kills the general case;
2. an upper bound on the number of all-multiple faces, which by Lemma B bounds the bridge
   ends at axis points and hence beta;
3. the solver run specified below.

C35 (splitting) would add "every triple point has >= 2 triangles in each alternating class",
but C35's use at t requires t - 1 to be closed first; that dependency is **not** satisfied
here (t = 5, 6 with beta >= 1 are open), so no clause below uses C35.

## SAT form (encoding spec)

Base: `build_defect(18, 94, K = t, alternate=True, exact_triple=True)` plus C10, as in
C32 (a) 1, with the k = 5 / k = 6 machinery reused. New clause groups:

1. **Triple-line pattern per cube.** Fix which lines carry triple points and how many
   (j_L). This fixes m and sigma = 3t - m; branch on patterns with 3t = sum_L j_L,
   j_L <= 8, and at most C(m,2)/3 triple points.
2. **Bridge literals.** `brg(L, P, Q)` for triple points P, Q on L: implies z[P], z[Q],
   "P and Q consecutive on L" (crossing-order literals), and that the segment is doubly
   used. Cardinality: sum brg <= sigma (A01), sum brg >= t - 6 + Z - C (R-e).
3. **Block literals and the D-count.** `blk(P, r, C)` with the four cap-triangle literals of
   C32 (a) 4; exact cardinality B + beta = 3t - 6 + Z (R-a) and B >= m + Z - 6 (R-c).
4. **Charging (A02).** `blk(P, r, C) and dbl(P, r±1) -> xpair(P, C)`; for axis points the
   unit form over all four non-middle rays.
5. **Lemma-A dichotomy (R-f).** For each point with two blocks: `touch(P) or xpair(P, C1) or
   xpair(P, C2)`, with sum_P touch(P) <= 2Z over the slack/unused literals already in the
   k = 5 encoding (C32 (a) 3 gives the "segment used with slack" form).
6. **Type restrictions (R-h).** For bridge ends: at an axis point require the all-multiple
   face literals of Lemma B; at a bent point forbid the back-ray bridge unless both cap
   second vertices are triple (verdict C07 fix); 1-block points need e >= 3 and 0-block
   points e >= 5 for c > 0 (C34 (b)).
7. **Symmetry.** Keep the chi(0, 1, 2) break and the line-0 rotation break of C32 (a) 7; do
   not assume line 0 avoids the triple points (at t >= 7 with m = 18 no such line exists).

Cube plan: branch first on (m, Z) with Z <= 2t + 6 - m, then on the triple-line pattern, then
on the block/bridge assignment of each point. At t = 7 the windows above leave
(m, Z, B, beta) in a set of size well under 200, each a rigid instance.

## Dependencies

A01, A02 (this stream, unrefereed); C34 (a), (b) and verdict C07 (refereed); Lemma A, Lemma B
and the x / Cred identity 2Z = sum kappa + Z_tr from `work/t3/general.md` (refereed);
C10, C32 (a) encoding blocks (refereed as specs). **Not** used: C35, C36.

## Test

`python3 work/t3/a_struct.py --selftest 200` checks (R-a), (R-b), (R-c), (R-d) and the A02
charging on exact arrangements, and prints m, sigma, B, beta, Z, sum_P c(P) per arrangement.
The arithmetic consequences at t = 7 were derived by hand from that system; no arrangement in
the repository has t >= 7 with beta > 0, consistent with `work/t3/shared.md`.
