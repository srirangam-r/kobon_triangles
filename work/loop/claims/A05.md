# A05 — Exact encoding specification for the A04 residue

**Proposed spec, not implemented CNF and not a solver closure.** Companion to the single A04 proof task. Settings: 18 pairwise-intersecting affine lines, no fourfold points, exactly t=7 or 8, T>=94. A combinatorial SAT model need not be stretchable; UNSAT rules out the encoded class, SAT alone supplies no geometric construction.

## Base and conventions

Use `search/kobon_sat.py:build_defect(18,94,t,allow_fourfold=False,alternate=True,exact_triple=True)` with its existing sign and crossing-order semantics. Do not import the k5/k6 special-case constraints. Optional C10 clauses are unconditional. Keep **only chi(0,1,2)!=-1** from earlier symmetry breaks, not 'line 0 avoids triples'. Do not impose C35/C38 alternating-sector lower bounds. The prior t=6 beta=0 closure is not the full predecessor closure required for splitting.

All auxiliary definitions below are **biconditionals**, compiled by Tseitin clauses; comparisons and sums use exact cardinality/PB encodings with fresh IDs strictly above the base CNF header. Reserve IDs through the same pool. Do not count mere witness variables that may be set false.

Let eq_r(i,j) mean i=j or z[sorted(r,i,j)]. For a crossing r intersect i, define

    rep(r,i) <-> AND_{j<i, j!=r} NOT eq_r(i,j).

This chooses the least non-r label of each vertex. Let mult(r,i) <-> OR_{j not in {r,i}} z[sorted(r,i,j)]. Each present triple z[p] denotes one physical point because fourfolds are forbidden. Define representative index of p on r in p as min(p minus {r}).

## Triangle and segment usage

The base triangle literals can underselect actual triangles. Strengthen them to equivalence with

    tri(i,j,k) <-> NOT z[i,j,k] AND
        consecutive_i(j,k) AND consecutive_j(i,k) AND consecutive_k(i,j),
    consecutive_r(i,j) = A(r,i,j) OR A(r,j,i).

In a straight-line arrangement these are precisely the bounded triangular faces. Keep the base uncut clauses as well. Add sum tri>=94 explicitly; the defect budget is only a redundant necessary bound here.

For each ordered r,i,j, define physical segment

    s(r,i,j) <-> rep(r,i) AND rep(r,j) AND A(r,i,j).

Exactly one such variable represents each bounded segment. A triangle q containing r uses that segment iff its two r-crossings equal i,j in either order. Let u(q;s) be this equality test AND tri(q) AND s. Then

    used2(s) <-> s AND atLeast2({u(q;s)}),
    unused(s) <-> s AND NOT OR_q u(q;s),
    bridge(s) <-> used2(s) AND mult(r,i) AND mult(r,j).

Set Z=sum unused and beta=sum bridge. Every geometrically realized model has at most two triangles per segment; an atMost2 constraint is safe. L1 forbids used2 with two simple endpoints. A block incidence for point p is a used2 segment with endpoint p and a simple other endpoint. This definition counts one block once, not four cap triangles. b_p is the sum of these incidences; B=sum_p b_p. Set centroid(p)<->z[p] AND b_p=3; C=sum centroid. Set n_i=sum_p (z[p] AND b_p=i). Introduce type-axis and bent by the opposition or nonopposition of the two middle rays in the fixed slope-labelled six-ray order at p. This distinguishes them even though both have b=2.

## Gap count and cap-gap clauses

For p<q as sorted line triples sharing line r, let i,j be their representative crossing indices. Orient by before(r,i,j), or use the reversed copy, never count both. Define g(r,p,q) iff z[p],z[q], before(r,i,j), and **no other triple point on r lies strictly between** them. Simple crossings do not obstruct g. Then sum g = sigma = 3t-m, where

    tl(r) <-> OR_{p contains r} z[p],     m=sum tl(r).

Define h=sum g-beta. Canonical cap-gap J variables are those g with exactly one internal vertex X and X simple. Equivalently there is a representative x with NOT mult(r,x), A(r,i,x) and A(r,x,j). This is an OR over x, not a sum over possibly concurrent labels.

A block whose cap is r and whose two outer neighbours p,q are triple implies this J variable. To express it without ray variables, use C10's witnesses: a block at P={a,b,c} with middle a, cap r, tri(a,b,r) and tri(a,c,r); its outer endpoints are b intersect r and c intersect r. If these are triple, they are exactly p,q. Group these incidences by J; at most two distinct block incidences per J (A04). The centroid then contributes three incidences. Add

    B+beta >= 3t-6+Z,
    3C <= 2h,
    m+Z+ceil(C/2) <= 2t+6.

The last inequality is equivalently 2m+2Z+C<=4t+12 because m,Z are integral. It is redundant but useful. It is not x-credit and must not be added to per-point m_P already containing x.

## Cubes and surviving cases

A04 proposes no t=7,m=18 model. The new high-m cubes are the **24 profiles for (t,m)=(7,17), 46 for (7,16), and 46 for (8,18)** in `a_gap_profiles.jsonl`. A row sets exact m,Z,B,beta,C,n0,n1,n2. It does **not** fix line 0 or assume all two-block points are axis. All values represent physical counts above.

Coverage for the other m is retained explicitly: t=7,m=7..15 or t=8,m=8..17. Enumerate C=0..t, 0<=Z<=2t+6-m-ceil(C/2), n0,n1,n2>=0 with n0+n1+n2+C=t, B=n1+2n2+3C and 0<=beta<=min(3t-m,3t-6), keeping B+beta>=3t-6+Z and 3C<=2(3t-m-beta). These are finite aggregate windows, not a claim that the geometric residue is already small. Distribute them into further triple-incidence cubes only if completeness is demonstrated.

Optional C34 restrictions retain all low-degree one/blockless points: e>=3 or e>=5 is **conditional on c>0**, not a blanket constraint. A04's isolated-axis touch bound may also be added using g-incidence: I<=2Z. C11 can add credits only after encoding both its non-cap and single-sided-entry hypotheses; several lines can touch the same unused segment, so do not replace I<=2Z by I<=Z.
