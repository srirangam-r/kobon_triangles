# A01. Bridge-line lemma: beta <= sigma, and what it forces at t >= 7

**Revision (round 2).** Operator-supplied referee correction applied: the threshold D-count uses >=, not equality. The signed A01 verdict file is not available in this checkout.

**Family.** n = 18, T >= 94 assumed, no 4-fold point, exactly t >= 7 triple points.
Notation as in `work/t3/shared.md` and `work/t3/general.md`: S = 288 - 3t, 3T = S - Z + D,
D = sum_P (b(P) + e(P)/2), B = sum_P b(P), beta = number of doubly used bridges,
j_L = number of triple points on the line L, m = #{L : j_L >= 1},
sigma = sum_L max(j_L - 1, 0) = 3t - m, C = number of centroid points (b = 3).

## Statement

1. **(Line bound.)** Every bridge is a bounded segment of the arrangement whose two
   endpoints are triple points, hence they are *consecutive* triple points on the line that
   carries it. A line L therefore carries at most max(j_L - 1, 0) bridges, and

   **beta <= sigma = 3t - m.**

2. **(Plane bridge graph.)** Two distinct bridges meet at most in a common endpoint, so the
   bridges form a plane straight-line graph on the t triple points with maximum degree <= 6;
   in particular beta <= 3t - 6 as well.

3. **(Consequences for a 94 with t >= 7.)** From D = B + beta >= 3t - 6 + Z:
   - **B >= m + Z - 6**;
   - with B <= 2t + C (b <= 2 at every non-centroid point): **m + Z <= 2t + 6 + C**;
   - writing n_i for the number of triple points with exactly i blocks,
     **n_2 + 2 n_3 >= B - t >= m + Z - 6 - t**.
   - beta >= 3t - 6 + Z - B, so **at least t - 6 + Z - C bridges** (C34 (a) restated), and by
     (1) at least that many pairs of triple points are consecutive on a shared line.

## Proof

1. A doubly used segment is a block middle (far end simple) or a bridge (both ends triple),
   by L1; so both endpoints of a bridge are triple points. A bounded segment of an
   arrangement has no vertex in its interior, so its endpoints are consecutive vertices of
   its line, hence consecutive triple points of that line. On a line with j_L triple points
   there are at most j_L - 1 consecutive pairs. Summing over the m lines that carry a triple
   point gives beta <= sum_L (j_L - 1) = 3t - m, because sum_L j_L = 3t (no 4-fold point).
2. Two segments of an arrangement meet only at a shared endpoint: an interior intersection
   point would be a vertex interior to a segment. A triple point has 6 rays and a bridge at
   P occupies the first segment of one ray, so the degree is at most 6. A simple plane graph
   on t >= 3 vertices has at most 3t - 6 edges.
3. Substitution. B <= 2t + C holds because block middles are pairwise non-adjacent rays, so
   b <= 3, with b = 3 only at centroid points. For the last line, B = n_1 + 2 n_2 + 3 n_3 <=
   t + n_2 + 2 n_3.

## SAT form

For each unordered pair of triple-point literals on a common line, define a bridge literal
`brg(L, P, Q)` equivalent to `z[P] and z[Q]`, consecutiveness as actual vertices, and
use of their segment by a triangle on each side. Count each physical segment once;
A05 gives the canonical representatives and full two-way definitions. Then add the cardinality clause
`sum_{L, P, Q} brg(L, P, Q) <= sigma` with sigma computed from the triple-line pattern of
the cube, and the D-count clause of C34 (a) in the form `B + beta >= 3t - 6 + Z`.
In cube form: once a cube fixes the triple lines (hence m and sigma), the bound
`B >= m + Z - 6` is a plain cardinality constraint over the block literals.

## Test

`python3 work/t3/a_struct.py --selftest 200`

Exact stdlib checker: recomputes triangles, Z, D, per-point blocks/bridges and checks
D = B + beta, the per-line bridge bound, beta <= sigma and the plane-graph property.
Result: 200 random exact arrangements (n = 8..11, 226 bridges in total), the 7-line bent
example of verdict C07 (b = 2, e = 4) with and without 4 extra far lines, and all
n = 15, 18 arrangements stored in the repository: **no failures**.

Note: the bound is tight in the fixtures (beta = 5, sigma = 8) but nowhere near an equality
in real 18-line arrangements with t >= 7, where beta = 0.
