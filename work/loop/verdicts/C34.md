# C34 verdict: the β > 0 toolkit for k ≥ 5 (D-count, points with c > 0, bent partners)

**Verdict: refereed-correct.** (a), (b) and (c) hold at every k (n = 18, no 4-fold point).
The only caveat is implementation detail for the SAT form of (a), noted below.

## (a) D-count

- S = 288 − 3k and 3T = S − Z + D, so T ≥ 94 ⟺ D − Z ≥ 3k − 6.
- By L1, D = Σ_P (b + e/2), because every doubly used segment is a block middle or a
  bridge.
- Hence Σc ≥ k − 6 + Z. ✓

**SAT form.** Z − D ≤ 6 − 3k with one representative per segment, taking the smallest
label at each endpoint, is exact. For the real assignment to satisfy it, the definitions
must be two-sided:
- "segment unused ⇒ unused(r,i,j)";
- "used2(r,i,j) ⇒ a triangle on each side".
Both must be guarded by the representative condition, i.e. ¬z(r,i,x) for x < i and the same
at j. A one-sided unused, true only if the segment is unused, would let the solver set it
false, and the constraint would carry no information. It would still be sound.

## (b) Which points can have c > 0

Every value was re-derived with no dependence on k.

**Type X.** b = 2, so c = e/2.
- The axis rays have simple far ends, so they are not bridges.
- A bridge on a non-axis ray needs its non-cap sector to be a triangle P Q R. Its third
  side lies on a new line through Q and R, because C1 and C2 each meet the needed lines on
  the wrong side. So PQR is an all-multiple face.
- Both rays bounding that sector then become bridges, so each face gives e = 2.
- There are two non-cap sectors, so e ∈ {0, 2, 4} and c ≤ 2. ✓

**Faces.**
- F1 is k-independent: the axis is b_P, because the rays toward Q and R have multiple
  first vertices; and the caps are b_Q and b_R, by the position-2 ray at R.
- F2 (at most 2 X vertices per face) uses referee3's argument: b_Q would cross line PR
  both beyond P and beyond R. It is k-independent.
- F3 (with two X vertices, the third vertex has ≤ 1 block, on its third line, with a triple
  cap, and is not bent) uses only the F1 structure at P and Q. It is k-independent. ✓
- At k ≥ 5, F1's "e = 2" becomes e ∈ {2, 4}, since a second face at P in (r3,r4) needs 2
  more triple points. C34 states this correctly.

**Bent.**
- The extra-bridge sets are exactly ∅, {0}, {4} and {0,4,5}.
  - Rays 0 and 4 need V0 and V4 multiple.
  - Bridges on both force ray 5 to be doubly used, with V5 multiple, or else P would have a
    third block and be a centroid.
  - Ray 5 alone forces both 0 and 4.
- So c ∈ {1/2, 1, 2}. ✓

**1-block, 0-block, centroid.** c = e/2 − 1, c = e/2 − 2, and c = 5/2 (e = 3 exactly).
These are all the types: adjacent middles are impossible, and b ≤ 3. ✓

## (c) Bent partners

- **P bent → Q.** Q's lines are PQ, C1 and C2, and a triple point has exactly 3 lines.
  Of Q's six rays:
  - The middles Q→X1 and Q→X3, C1 beyond Q, and C2 beyond Q would need caps ℓ1 or ℓ0 to
    cross the wrong half of C2 or C1. Both ℓ1 ∩ C2 = V4 and ℓ0 ∩ C1 = V0 lie on P's side.
  - The ray Q→P has a multiple far end.
  - So only the middle on PQ beyond Q is possible. ✓
- C21 Claim 1 (≤ 2 bent points toward Q, opposite, and then Q blockless) uses only this
  fact and ray adjacency, so it is k-independent. ✓
- **The charging bounds** are sums of the per-type bounds, so they are correct.
  - Recall that a bridge adds 1/2 at each end, so 1 to Σc, matching D.

## Tests

Two scripts were run: `work/referee4/c34_test.py` (6,000 contracted and flipped
arrangements) and `c34_bent_gen.py` (greedy bent- and bridge-seeking contractions, 4,118
intermediate arrangements). Together that is 10,118 arrangements, with k from 4 to 10+ and
most at k ≥ 5. **0 failures** in all of the following:

- **D = Σ(b + e/2)** in every arrangement.
- **Type X** (11,873 at k ≥ 5):
  - bridges only on the two rays of a non-cap sector holding an all-multiple face, and
    both rays whenever there is a face;
  - e ∈ {0, 2, 4};
  - 528 X points with e = 2, **1 with e = 4** (two faces, c = 2).
- **Bent** (96 points, all k ≥ 5): extra sets ∅/{0}/{4}/{0,4,5} only, including **1 with
  {0,4,5} (c = 2)**.
- **Bent partners** (96): always 0- or 1-block, with the 1-block middle on PQ beyond Q.
  No sample had two bent points toward one Q, so C21 Claim 1 remains checked by hand.
- **Faces:** no face with 3 X vertices. No sample had a face with 2 X vertices, so F3
  remains checked by hand.
- **Values of c > 0 seen:** X 1 and 2; bent 1 and 2; 1-block 0.5 and 1.5 (e = 3, 5);
  0-block 1 (e = 6).

The explicit exact bent example with c = 2 (C07 verdict, `c7_bent_example.py`) also fits.
